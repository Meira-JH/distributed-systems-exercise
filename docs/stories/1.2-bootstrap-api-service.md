# Story 1.2: Bootstrap The API Service

## Epic

[Epic 1: Run The System Locally](/Users/jm/Documents/Github/Meira-JH/distributed-systems-exercise/docs/epics/1-run-system-locally.md)

## Status

`not ready`

This story depends on the workspace bootstrap and shared database baseline being in place first.

## Goal

Create a minimal API service that can start, connect to the shared TypeORM database layer, and expose a health endpoint.

## Problem

The local system needs at least one runnable application service before we can prove that Docker, TypeORM, and NGINX routing are wired correctly.

## Scope

This story includes:

1. `apps/api/package.json`
2. `apps/api/tsconfig.json`
3. API server startup
4. shared database initialization
5. `GET /health`
6. configuration for running as both `api-1` and `api-2`

This story does not include business features like auth, orders, payments, or permissions.

## Deliverables

1. `apps/api/src/server.ts`
2. `apps/api/src/app.ts`
3. `apps/api/src/config.ts`
4. minimal route registration for `/health`

## Acceptance Criteria

1. the API service starts in Docker
2. the service initializes the shared TypeORM `DataSource`
3. `GET /health` returns a successful response
4. the same service image can run as both `api-1` and `api-2`
5. startup logs clearly show instance identity and readiness

## Dependencies

1. Story 1.1 completed
2. Story 1.5 available enough to initialize the shared `DataSource`

## Final Task

Create or update the necessary documentation inside `docs/` to reflect any setup steps, behavior, commands, or operational notes introduced by this story.

## Out Of Scope

1. authentication
2. payments
3. background job creation
