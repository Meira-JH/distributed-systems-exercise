## Goal

Create the minimal repository structure, root workspace configuration, basic local PostgreSQL container configuration, and repository-wide environment management baseline needed to support local development for the distributed systems practice lab.

## Problem

Before any service can run, the repository needs a predictable local development foundation. That includes a basic local PostgreSQL container definition, a repo-wide `.gitignore`, and a clear `.env` strategy, because the API, worker, Docker Compose, and TypeORM layer all depend on the database and configuration existing in a known way from the start.

## Scope

This story includes:

1. root `package.json`
2. npm workspace configuration
3. root scripts for build, migrations, seed, and local startup
4. base TypeScript configuration
5. initial folder structure for apps, packages, scripts, docker, and docs
6. basic local PostgreSQL Docker configuration
7. root `.gitignore`
8. root `.env` templates and env-var management conventions

Basic local PostgreSQL configuration means:

1. a `postgres` service in `docker-compose.yml`
2. `POSTGRES_USER`, `POSTGRES_PASSWORD`, and `POSTGRES_DB`
3. a persistent volume
4. a `pg_isready` healthcheck
5. port `5432` exposed for local debugging

Environment management means:

1. a committed `.env.example` with all required keys for local development
2. optional environment-specific templates when needed, such as a Docker-oriented example file
3. a clear convention for which files are committed and which are local-only
4. a root `.gitignore` that prevents accidental commits of secrets and generated files
5. consistent variable naming across Node services, TypeORM, and Docker Compose

This story does not include database schema design, TypeORM entities, or migrations. Those stay in the shared database-layer story.

## Deliverables

1. root `package.json`
2. `tsconfig.base.json`
3. initial directory structure for:
   `apps/`, `packages/`, `scripts/`, `docker/`, `docs/`
4. initial `docker-compose.yml` with a working `postgres` service definition
5. root `.gitignore`
6. root `.env.example`
7. any additional committed env template files needed for efficient local setup
8. short documentation for env-var usage and file ownership

## Acceptance Criteria

1. the repository has a valid root `package.json`
2. npm workspaces are configured for `apps/*` and `packages/*`
3. root scripts exist for:
   build, `dev:api`, `dev:worker`, `dev:provider`, `db:migrate`, `db:revert`, `db:generate`, `db:seed`
4. `tsconfig.base.json` exists with TypeScript settings required for TypeORM
5. the project folders referenced in the docs exist
6. the workspace documentation references Node.js `24.x` or later for local development
7. `docker-compose.yml` includes a basic `postgres` service
8. the `postgres` service defines database credentials, persistent storage, and a healthcheck
9. the basic PostgreSQL container configuration is ready for the later API and worker stories to depend on
10. a root `.gitignore` exists for the whole repository
11. `.gitignore` excludes at least local env files, dependency folders, build output, logs, and OS/editor noise
12. a committed `.env.example` exists with the required variables for local development
13. the env-var strategy clearly distinguishes committed templates from local secret-bearing files
14. env variable names are consistent between Docker Compose, TypeORM, and the Node services

## Dependencies

1. Node.js `24.x` or later and npm installed locally

## Final Task
