# Story 1.3: Bootstrap The Worker

## Epic

[Epic 1: Run The System Locally](/Users/jm/Documents/Github/Meira-JH/distributed-systems-exercise/docs/epics/1-run-system-locally.md)

## Status

`not ready`

This story depends on the workspace bootstrap and shared database baseline being in place first.

## Goal

Create a minimal worker process that starts, initializes TypeORM, and remains connected to PostgreSQL.

## Problem

The local baseline needs a running worker process because later exercises depend on background processing, retries, and reconciliation. Even before queue behavior is implemented, the worker must be able to boot reliably.

## Scope

This story includes:

1. `apps/worker/package.json`
2. `apps/worker/tsconfig.json`
3. worker startup entrypoint
4. shared TypeORM initialization
5. worker readiness logging

This story does not require actual queue polling or retry logic yet.

## Deliverables

1. `apps/worker/src/worker.ts`
2. minimal worker startup log flow

## Acceptance Criteria

1. the worker container starts successfully
2. the worker initializes the shared `DataSource`
3. the worker process stays alive after startup
4. logs confirm successful boot and database connectivity

## Dependencies

1. Story 1.1 completed
2. Story 1.5 available enough to initialize the shared `DataSource`

## Out Of Scope

1. job polling
2. retry policy
3. dead-letter handling
